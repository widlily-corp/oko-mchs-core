## 0. Общая цель команды
Создать **работающий программно-аппаратный комплекс мониторинга ЧС**:
1. **Симуляция (Gazebo 11 + ROS 2):** Дрон взлетает, облетает зону лесного массива по заданному маршруту («змейка»).
2. **Компьютерное зрение (OpenCV / AI):** В режиме реального времени находит очаг пожара/задымления, очерчивает его рамкой и рассчитывает координаты.
3. **АРМ Оператора (CustomTkinter UI):** Выводит живую картинку с дрона, тактическую карту, высоту, заряд батареи и тревожные оповещения.
4. **Отчетность:** Автоматически формирует итоговый протокол инцидента для ЦУКС МЧС.
5. **Защита:** Эффектная презентация + пояснительная записка с ТТХ дрона.

        │   [Рома: mchs_vision]

                  │
        [Соня: mchs_ui] ──► Отображает оператору видео, карту, телеметрию

## 3. Персональные микро-ТЗ для каждого участника

* **Задача 1: АРМ Оператора МЧС (`src/mchs_ui/app.py`)**

  * Нужно: запустить `python src/mchs_ui/app.py` на Windows.
  * Докрутить визуал: подобрать сочные цвета (МЧС-оранжевый `#FF6B35`, темно-синий графит), проверить переключение обычного режима и тепловизора (кнопка `ТЕПЛОВИЗОР`), анимацию тревоги при детекции пожара.
* **Задача 2: Презентация проекта (`docs/presentation/`)**
  * Подготовить слайды (PowerPoint / Canva / Figma):
    1. Титул: «Око МЧС: Автономный комплекс раннего обнаружения лесных пожаров».
    2. Проблема: скорость реакции спасателей и ущерб от верховых пожаров.
    3. Наше решение: автономный БПЛА + бортовой ИИ + онлайн-пульт штаба.
    4. Архитектура: как взаимодействуют Gazebo, ROS 2, OpenCV и UI.
    5. Экономика: сравнение стоимости пилотируемой авиации (Ми-8) и нашего БПЛА.
* **Задача 3: 3D-рендеры и визуал**
  * Сгенерировать эффектные концепт-арты дрона над горящим лесом и схемы для презентации.

### 👨‍💻 РОМА (Компьютерное зрение / Vision Lead)
**Твоя суперсила:** Алгоритмическая обработка изображений и надежная математика.
* **Задача 1: Нода детекции огня (`src/mchs_vision/scripts/mchs_vision_node.py`)**
  * Вход: топик `/mchs/camera/image_raw` из симулятора (или тестовое видео/вебкамера).
  * Реализация: 
    1. Цветовая сегментация HSV: пламя имеет диапазон `H: [5..25], S: [120..255], V: [150..255]`.
    2. Морфологическое удаление шума (`cv2.morphologyEx`, `cv2.dilate`).
    3. Поиск контуров `cv2.findContours`. Фильтрация по минимальной площади `cv2.contourArea(c) > 400`.
    4. Отрисовка ограничивающего прямоугольника и надписи `🔥 ОЧАГ ВОЗГОРАНИЯ | ТРЕВОГА!`.
* **Задача 2: Оценка координат очага**
  * По положению центра рамки $(u, v)$ на кадре и высоте дрона $Z$ рассчитать отклонение очага от центра дрона:
    $$\Delta X = \frac{u - w/2}{w} \cdot Z \cdot 2\tan(\text{FOV}/2)$$
    $$\Delta Y = \frac{v - h/2}{h} \cdot Z \cdot 2\tan(\text{FOV}/2)$$
  * Публиковать координаты в топик или лог для оператора.

---

### 👨‍💻 АРТЁМ (Полетные алгоритмы & Документация)
**Твоя суперсила:** Логичные, пошаговые скрипты и аккуратная документация.
* **Задача 1: Полетный контроллер патрулирования (`src/mchs_control/scripts/mchs_pilot_node.py`)**
  * Стартовый скрипт уже лежит в репозитории.
  * Нода публикует сообщения `geometry_msgs/Twist` в топик `/mchs/cmd_vel`.
  * Нужно доработать логику облета:
    - Фаза 1: Взлет и набор высоты (Z = 5.0 м).
    - Фаза 2: Полет по сетке (прямо 15 сек → разворот на 90° → смещение на 5 м → разворот → полет обратно).
    - Фаза 3: При получении сигнала о пожаре — зависание на 5 секунд над очагом.
    - Фаза 4: Возврат на точку старта (RTL).
* **Задача 2: Генератор протокола инцидента (`src/mchs_control/scripts/generate_report.py`)**
  * Скрипт сохраняет `incident_report.json`: время обнаружения, координаты очага, площадь возгорания, уровень угрозы (ВЫСОКИЙ), статус оповещения пожарных расчетов.
* **Задача 3: Техническая пояснительная записка (`docs/tech_note/`)**
  * Заполнить характеристики выбранного БПЛА (масса: 4.8 кг, дальность: 25 км, АКБ: LiPo 6S 22000 мАч, время полета: 45 мин, камера: 4K Sony IMX + тепловизор 640x512).

## 4. Правила работы с Git (чтобы не сломать проект)

1. **Никаких прямых пушей в ветку `main`!**
2. Каждый создает свою ветку от `main`:
   * Соня: `git checkout -b feature/ui-sonya`
   * Рома: `git checkout -b feature/vision-roma`
   * Артём: `git checkout -b feature/pilot-artem`
3. Когда задача проверена — создается Pull Request на GitHub, капитан жмет «Merge».
4. В Git коммитим **только исходники** (никаких `.tar`, `.whl`, `build/`, `install/` — `.gitignore` уже настроен).
