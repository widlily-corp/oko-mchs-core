# Живой АРМ: дрон на карте, сканирование всей арены, подвижные очаги, отчёты

Документ описывает обновлённую демонстрацию «ОКО МЧС»: дрон виден на карте АРМ
в реальном времени, летает не по точкам, а сканирует змейкой всю арену
200×200 м, очаги ЧС можно перетаскивать прямо на карте, а фото/видео/протоколы
сохраняются в `reports/`.

## 1. Как запустить (одна команда)

Из корня репозитория на Windows:

```powershell
run_all.bat        # или: powershell -File run_all.ps1
```

Или вручную:

```bash
wsl.exe -d Ubuntu-22.04 -e bash -c "cd /root/oko-mchs-core && MCHS_NO_UI=1 bash scripts/run_all.sh"
# окно АРМ оператора (если не открылось само):
python "\\wsl.localhost\Ubuntu-22.04\root\oko-mchs-core\src\mchs_ui\app.py"
```

Что происходит:

1. `run_all.sh` перегенерирует мир по текущим очагам из `config/hazards.json`
   и поднимает `gzserver` с ареной 200×200 м;
2. нода зрения `mchs_vision_node` публикует аннотированный кадр, телеметрию
   (`http://127.0.0.1:8080/state.json`) и отдаёт MJPEG-стрим на Windows;
3. автопилот `mchs_pilot_route.py` сканирует арену змейкой (ряды/шаг — в
   `config/mission.json`), публикует статус в `/mchs/scan_status`;
4. АРМ на Windows показывает живой кадр, реальное положение дрона на карте,
   план сканирования, тревоги по подтверждённым очагам и пишет отчёты.

## 2. Дрон на тактической карте

АРМ каждые 200 мс опрашивает `GET /state.json`:

```json
{
  "ts": "14:56:00",
  "drone": {"x": -49.0, "y": 21.1, "z": 22.0, "yaw_deg": 63.0,
            "body_yaw_deg": 0.0, "speed_mps": 12.0, "battery_pct": 96.0},
  "scan": {"row": 3, "rows_total": 7, "progress": 0.42, "phase": "СКАНИРОВАНИЕ"},
  "detection": {"last_event": {"hazard_type": "FIRE", "threat_level": "CRITICAL",
                               "area_sq_m": 54.9, "x": 61.3, "y": 25.8, "ts": "14:56:00"},
                "counts": {"FIRE": 3, "SMOKE": 1, "OIL_SPILL": 0, "FLOOD": 2}},
  "reports": {"incidents_dir": "reports/incidents",
              "last_photo": "reports/incidents/INC-2026-008_145601.jpg",
              "protocol": "reports/incident_protocol.json", "photo_count": 3}
}
```

В живом режиме АРМ рисует на карте фактический маркер БПЛА («БПЛА»), курс
по направлению полёта, конус обзора, трек и подпись «СКАНИРОВАНИЕ: РЯД k/N ·
NN%». Телеметрия (высота/скорость/координаты/курс) — реальная, а не
демонстрационная. Если сервер :8080 недоступен, АРМ работает в прежнем
синтетическом режиме (демо без Gazebo).

## 3. Сканирование всей арены (не по точкам)

`config/mission.json` задаёт зону и шаг змейки:

```json
"scan": {"x_min": -92.0, "x_max": 92.0, "y_min": -84.0,
         "y_max": 84.0, "row_step_m": 28.0}
```

Это 7 рядов по 184 м: дрон идёт по X, на краю смещается на 28 м по Y и
возвращается в обратную сторону — и так по кругу всю демонстрацию. Скорость
12 м/с, около 2 минут на полный проход арены. Все 4 очага из
`config/hazards.json` попадают в полосу сканирования (ряды y = −84, −56, −28,
0, 28, 56, 84), поэтому детектор проходит рядом с каждым из них.

Файл-команды оператора: АРМ пишет `reports/mission.cmd` (`rtl` — возврат на
базу, `scan` — продолжить), автопилот читает и удаляет файл.

## 4. Как менять положение очагов

Два слоя:

1. **Из АРМ (для демонстрации):** на тактической карте нажмите мышью на маркер
   очага (ПОЖАР / НЕФТЬ / ПАВОДОК / СВАЛКА) и перетащите его в нужную точку.
   При отпускании:
   - новые координаты сохраняются в `config/hazards.json`;
   - в фоне вызывается `arena_controller.py`, и модель очага в Gazebo
     переезжает на новое место **без перезапуска**;
   - маркер, карточка инцидента и протоколы используют новые координаты.
2. **Из консоли WSL:**

```bash
cd /root/oko-mchs-core
python3 src/mchs_simulation/scripts/arena_controller.py --hazard fire --x 20 --y -15
python3 src/mchs_simulation/scripts/arena_controller.py --random   # разбросать все 4 очага
python3 src/mchs_simulation/scripts/arena_controller.py --list     # список очагов
```

> При следующем запуске `run_all.sh` мир перегенерируется по
> `config/hazards.json`, поэтому перетащенные очаги остаются на своих местах.

## 5. Отчёты: где фото, видео и протоколы

Все материалы — в `reports/` (на Windows:
`\\wsl.localhost\Ubuntu-22.04\root\oko-mchs-core\reports`, в АРМ кнопка
«📂 ОТЧЁТЫ» / `Ctrl+O`):

| Путь | Содержимое |
|---|---|
| `reports/incidents/*.jpg` | фото очагов с HUD, автоматически при подтверждённой детекции рядом с очагом |
| `reports/photos/snapshot_*.jpg` | ручные снимки оператора (кнопка «📸 СНИМОК», клавиша `P`) |
| `reports/video/record_*.mp4` | видеозапись бортовой камеры (кнопка «● ЗАПИСЬ», клавиша `R`, MP4 ~12 к/с) |
| `reports/incident_protocol.json` | последний протокол инцидента (пишет борт), его же читает АРМ для тревоги |
| `reports/incident_protocol_*.json/.txt` | ручной экспорт протокола оператором (JSON / бланк TXT) |
| `reports/mission.cmd` | файл-команда автопилоту (`scan`/`rtl`) |

Подробности — в [`reports/README.md`](../reports/README.md).

## 6. Логи

| Путь | Содержимое |
|---|---|
| `logs/system.log` | сводный журнал всех подсистем |
| `logs/events.jsonl` | машиночитаемые события (JSON Lines) |
| `logs/gcs_ui.log` | журнал АРМ |
| `logs/stdout/gazebo.log` | консоль gzserver |
| `logs/stdout/vision.log` | консоль ноды зрения |
| `logs/stdout/pilot.log` | консоль автопилота |

Быстрая проверка после запуска:

```bash
cd /root/oko-mchs-core
curl -s http://127.0.0.1:8080/state.json | head -c 400; echo
tail -5 logs/stdout/pilot.log
ls -la reports/incidents reports/photos reports/video 2>/dev/null
```

## 7. Известные ограничения

- Детектор классический (HSV + трекинг), поэтому возможны ложные срабатывания
  на тёмных/серых поверхностях и ярких бликах. Протокол ЦУКС формируется
  только для детекций, подтверждённых рядом с очагом из `config/hazards.json`
  (радиус 30 м), — ложные пятна в других местах тревогу в АРМ не поднимают.
- Камера наклонена на 45° вперёд, поэтому полоса обзора смещена вперёд по
  курсу; при разворотах дрона (движение по −X) камера смотрит в сторону
  пройденного ряда.
- Высота 22 м обеспечивается кинематическим плагином и нулевой гравитацией
  демо-арены: дрон не выполняет физическую посадку, а «висит» на эшелоне.
- Окно Gazebo (gzclient) в WSLg не показывается — весь визуал идёт в АРМ
  оператора через `:8080`.
